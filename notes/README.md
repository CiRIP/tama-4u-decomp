# Analysis notes

Two independent read-throughs of the firmware wrote the comments in `src/`. Their notes are kept here as they were written. Addresses in them are the original firmware's: in this fork the code and the RAM variables are placed by the linker, so only the fixed addresses (hardware, the flash layout, the API, the save layout) still hold.

* `fable/`: NOTES.md (findings by area), peripherals.md (register inventory), symbols.tsv (about 430 names), sigcheck.py (checks the TAMAGO signature of every record in the dump).
* `opus/`: NOTES.md, peripherals.md, symbols.tsv (about 200 names).
* `findings/`: one report per investigated topic (nfc, tamago, cards, spots, lcd, sessions, sound, ir, testmode), checked against the datasheets, the download pack and emu4u.
* [IMPROVEMENTS.md](IMPROVEMENTS.md): source improvements noted for later (byte-identical), e.g. the system clock as one constant.
* [source_files.md](source_files.md): the source files, what each is for, their former ids (F28_24110A6, G_2513FC6, R10 ...) and the boundaries still open.

The two disagreed in places. Where a point has been settled since, the answer below overrides the notes; the comments in `src/` follow it. Points still open are in [OPEN.md](OPEN.md).

## Settled

1. **CPU clock: 30 MHz** (not 29.49 MHz). The board has a 30 MHz crystal. The 9600-baud reload of 195 fits 30 MHz (29.4912 MHz would need 191), and the millisecond delays count 30000 per ms.
2. **NFC timeout tick: 100 ms** (not 10 ms). nfc_tick_start runs T16 ch.3 at MCLK/64 with compare 0xB71B: 30e6 / 64 / 46876 = 10 Hz, so the "d * 10" timeouts are in seconds, counted from the moment each function opens the link. The PN512's own timer is programmed but never used ([findings/nfc.md](findings/nfc.md)).
3. **TAMAGO files** ([findings/tamago.md](findings/tamago.md), checked on the 916 files of the download pack, all appended to a JPEG): name UTF-16BE at 0x06, every multi-byte field big-endian (size at 0x48), type / category / sub-kind at 0x4E / 0x4F / 0x51, item id 0x5A, display name 0x5E, item effects 0x74..0xBC, body from 0x200, a 16-bit sum at the end. The exchange records the toys build in RAM use the same magic but are little-endian (size at 0x48, sum). The firmware never checks a downloaded file's own signature or sum: comm_validate_record only checks exchange records.
4. **NFC modes** ([findings/nfc.md](findings/nfc.md), PN512 datasheet): toy to toy is NFCIP-1 active mode at 424 kbit/s (TxMode/RxMode 0xA1), the sender always the initiator; the phone app is reached as a passive 106 kbit/s Type A initiator, then NFC-DEP + LLCP + SNEP; tags and cards are read in Type A reader mode (cards switched to 424k by PPS); a FeliCa poll can detect but not read a FeliCa card. No card emulation. The PN512 is on EFSIO ch.1, 8N1, at about 460 kbaud during sessions. Our NFCID3 is random (F0 40 + 4 random bytes).
5. **LCD** ([findings/lcd.md](findings/lcd.md)): the P07 strap, read once at boot by lcd_init (pull-up on, result in lcd_is_st7735), selects the controller: high = Sitronix ST7735 (verified; lcd_init_st7735), low = an Ilitek ILI9163-family controller (inline in lcd_init; lcd_init_ili9163_old is an unused older copy). The panel is 128 x 128, driven in the controllers' reset 18-bit mode over an 8-bit bus (#CE8), with dirty-rectangle updates from a 128 x 72 indexed frame buffer at 0x1810; sleep is SLPIN / SLPOUT only.
6. **The old serial exchange is the IR link of the earlier models** ([findings/ir.md](findings/ir.md)): an NEC-style pulse-distance code with a 62 kHz carrier on P05 (LED) / P04 (receiver) / P03 (transceiver shutdown), 20-byte packets with an 8-bit sum. It cannot run: the session layer is stubbed out (the transfer routine and its abort are empty, so this source leaves them out; ir_send_data_stub returns 0) and the receive interrupt is not in the vector table. The one hidden menu entry is reachable only by toggling the P06 strap in the menu.
7. **Touch cards** ([findings/cards.md](findings/cards.md), matches emu4u): ISO-DEP cards whose ATS holds "TNPS064"; every access is RATS, PPS to 424k, AUTHENTICATE 90 1B with the 8-byte key D_255D378, then READ 90 AD / WRITE 90 8D on file 2 (0x3C bytes: use counter, two 0x18-byte owner slots = name + birthday, sum) or file 3 (0x30-byte header, then content read straight into flash 0x2050000). There is no SELECT. Content type 0x65 delivers characters and TAMAGO items, 0x66 a bingo card. A card registers to at most 2 owners; registration and the use counter exclude each other.
8. **Touch Spots** ([findings/spots.md](findings/spots.md)): the reader accepts exactly two kinds of tag, a 48-byte Type 2 tag (MIFARE Ultralight / NTAG210, capability container BuiltinItemKeyEntry 10 06 00; a 0x30-byte record: use counter, kind, bingo spot id, flags, parameter, 36 characters of text, sum) and the ISO-DEP card. The firmware has no spot / card flag: a Type 2 record can only deliver events, messages, points, visitors and bingo numbers (kinds 1-4, 6-10), never TAMAGO files. Spots are told apart only by the bingo spot id and the UID of the previous touch ("not twice in a row"). Which technology the store spots used cannot be decided from the code.
9. **Idle touch and the communication count** ([findings/spots.md](findings/spots.md)): any RF field that does not start a Tamagotchi exchange within 2 s counts as a reader touch; readers are not identified, every touch counts. comm_count is the general communication count (sessions, idle touches, spots, bingo, gashapon; capped at 1001). Its thresholds: 5 house level 1, 5 / 10 notebook animations, 20 house level 2 and new town places, 50 であいストリート, 100 house level 3, 1000 house level 4.
10. **Session types** ([findings/sessions.md](findings/sessions.md)): the menu choice passed to nfc_menu_session (1..7) maps to the session type carried in byte 0x4C of the records: 2 greeting, 3 / 4 game rounds, 5 gift, 6 proposal, 7 photo, 8 app link (and debug item send), 1 the test-mode link test, 0 the idle target. 0xF0EF from the peer detection means "no Tamagotchi" (in the idle path: a phone or reader touched us).
11. **Sound** ([findings/sound.md](findings/sound.md)): only T16 ch.0 and ch.1 make sound, the same melody on both with one output inverted: a piezo between P10 and P11 driven from both ends (wiring inferred). The library could drive 4 voices; ch.2 is the backlight PWM, ch.3 the 100 ms tick, ch.4 the sequencer tick, ch.5 delays. No volume control. The sound bank snd_bank holds 83 sounds.
12. **Downloaded programs** ([findings/tamago.md](findings/tamago.md)): games and outings are S1C33 code linked for 0x2000000 with the header included; dl_install_program copies them there and the town menu / game corner calls 0x2000000 + be32(0xAE). They call only the firmware API block 0x2400AD0..0x2401D92 and keep their globals at RAM 0x84740..0x847BF. sys_apply_patch_list (a patch-list routine) is dead code.
13. **Flash 0x2050000 (sector 13)** is a shared scratch sector ([findings/cards.md](findings/cards.md)): the card download, the friend portrait staging after a greeting, and the message editor's rendered pictures each erase and use it within one flow. There is no character-creation record.
14. **Test mode** ([findings/testmode.md](findings/testmode.md)): entered by pressing A, C, A, B, C within about 3 s of the start-up picture (test_check_entry_code -> test_mode). It tests LCD colours, sleep, the RTC, battery, ROM sums, flash (erasing all user data: a factory reset), sound, NFC and the touch reader, and an NFC link. The P06 strap enables debug features: "DB ON", no screen timeout, game-clock fast-forward on C, the debug communication menu.
15. **Life stages: there is no teen stage** (confirmed by the device owner). pet_life_stage (the character table's stage byte): 0 egg, 1 baby (ids 0..3), 2 child (4..13), 3 adult (16..21, 1001..1006: まめっち, くちぱっち, めめっち, ...), 4 a special form of an adult (2001..2010, 3001..3010: やんちゃまめっち, くちぱっちん, ...; reached by evo conditions, reverts to its base adult with evo_revert_special_form when the condition lapses), 5 only a downloaded character's own stage byte (handled like 3). Names and comments that say "teen" for stage 3 or "adult" for stage 4 are wrong.
